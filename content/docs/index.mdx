**Nexalware is AIoT infrastructure that lets your software and AI agents
communicate with and control your physical devices and machines through a
single API.**

If your application needs to turn on a pump, read a sensor, open a gate,
move a vehicle, monitor a machine, or coordinate physical systems, Nexalware
provides the infrastructure that connects your software to those systems.

Instead of building device connectivity, authentication, command handling,
telemetry, and automation yourself, you connect your application to
Nexalware and work with your physical systems through a consistent API.

```text
   YOUR SOFTWARE
   AI Agent · Backend · App
            │
            │  Nexalware API
            ↓
       ┌───────────┐
       │ NEXALWARE │
       └─────┬─────┘
             │
             ↓
     YOUR PHYSICAL DEVICES
   ┌─────────┬─────────┬─────────┐
   ↓         ↓         ↓         ↓
 Device    Machine   Vehicle   Sensor
```

## Devices that coordinate other devices

Today, the Nexalware API is centered around devices. A device can represent
a smart socket, pump, sensor, motor, gateway, or another connected physical
system, each with its own identity, capabilities, state, and permissions.

One device can also go a step further and act as a **master**, coordinating
a whole team of other physical devices connected to it locally over WiFi or
Bluetooth, no internet needed between them, see
[Device Orchestration](/docs/device-orchestration). Those coordinated
devices are called **sub-devices**, not "agents", they're still physical
hardware, just smart enough to relay commands and report state for
whatever is connected behind them. "AI agent" stays the term for the
software calling Nexalware, never for the physical devices themselves.

```text
   Your App / AI Agent
           │
           ↓
       Nexalware
           │
           ↓
     Master Device
           │
     ┌─────┼─────┐
     ↓     ↓     ↓
   Sub-   Sub-   Sub-
  device device device
```

## How the API fits in

The Nexalware API is the interface between your application and the
Nexalware platform. Your application uses the API to:

- discover devices
- read device state
- read telemetry
- send commands
- receive events
- create automations
- manage authorized access

Physical devices connect to Nexalware's infrastructure through supported
device communication protocols. For the current platform, devices connect
through MQTT. Your application does not need to manage that MQTT connection
when using the HTTP API - but if you're writing the firmware for the device
itself, see the [MicroPython Reference](/docs/micropython-reference) or
[Arduino IDE / C Language Reference](/docs/arduino-reference).

```text
Your Application
       │
       │ HTTP API
       ↓
   Nexalware
       │
       │ Device connectivity
       ↓
      MQTT
       │
       ↓
    Device
```

The protocol used underneath can change without requiring your application
to change how it works with Nexalware.

## Authentication and access

Nexalware separates human access from application access.

### API keys

API keys are used by applications, backend services, scripts, and
integrations. An API key must have a DeviceGrant that defines which devices
and commands it can access.

```text
X-Api-Key: your_api_key
```

### Dashboard sessions

Dashboard sessions are used by people logged into the Nexalware dashboard.
Dashboard-only actions include:

- creating devices
- creating API keys
- managing DeviceGrants
- creating schedules
- creating rules

The [API Reference](/docs/reference) shows which authentication mode each
endpoint requires.
